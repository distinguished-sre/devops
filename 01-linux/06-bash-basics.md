## Теория

### Переменные, кавычки и подстановки

Скрипт (script) это текстовый файл с командами, которые оболочка (shell) выполняет по порядку. Первой строкой идёт shebang: `#!/usr/bin/env bash` говорит системе, чем запускать файл.

```bash
#!/usr/bin/env bash
NAME="мир"                     # присваивание: без пробелов вокруг "="
echo "Привет, ${NAME}"         # значение переменной в двойных кавычках
echo 'Привет, ${NAME}'         # в одинарных кавычках подстановки нет
TODAY="$(date +%F)"            # результат команды в переменную
PORT="${PORT:-8080}"           # значение по умолчанию, если PORT не задана
echo "Скрипт: $0, первый аргумент: ${1:-нет}, всего аргументов: $#"
```

Три правила, которые ловят новичков. Пробелы вокруг `=` запрещены: `NAME = "мир"` оболочка прочитает как команду `NAME` с аргументами. Переменные всегда берёшь в двойные кавычки: `"${FILE}"`, иначе имя файла с пробелом развалится на два аргумента. Обычная переменная видна только текущему процессу; чтобы её увидели дочерние процессы (например, `python3 app.py`), нужен `export PORT=9000` или запись в одну строку `PORT=9000 python3 app.py`. Именно так `app.py` получает `HOST`, `PORT`, `NOTES_DATA`.

> **Проверь понимание:** чем отличается `echo "$HOME"` от `echo '$HOME'` и почему `FILE=my notes.txt` не сработает?

<details>
<summary>Ответ</summary>

В двойных кавычках оболочка подставляет значение (`/home/user`), в одинарных выводит текст как есть (`$HOME`). В `FILE=my notes.txt` после пробела начинается новая команда `notes.txt`, а `FILE=my` действует только на неё. Правильно: `FILE="my notes.txt"`.

</details>

### Код выхода и условия

Каждая команда завершается с кодом выхода (exit code): 0 значит «успех», всё остальное «ошибка». Код последней команды лежит в `$?`. Условия в bash проверяют именно код выхода, а не «истину» в привычном смысле.

```bash
if grep -q "notes" /etc/passwd; then      # -q: ничего не печатать, только код
  echo "пользователь есть"
elif [ -d /var/lib/notes ]; then          # [ ... ] это команда test
  echo "нет пользователя, но каталог есть"
else
  echo "ничего нет"
fi

[ -f app.py ] && echo "app.py на месте"   # && выполнит вторую команду при коде 0
[ -f app.py ] || echo "нет app.py"        # || выполнит вторую команду при коде не 0
```

Проверки в `[ ]`: `-f` обычный файл, `-d` каталог, `-z "$X"` строка пустая, `-n "$X"` не пустая, `"$A" = "$B"` строки равны, `"$N" -gt 5` число больше пяти. Скобка `[` это команда, поэтому пробелы внутри обязательны: `[ -f app.py ]`, а не `[-f app.py]`. Свой код выхода скрипт задаёт командой `exit 3`. Договорись сам с собой: 0 успех, 1 проверка не прошла, 2 неверные аргументы.

> **Проверь понимание:** что напечатает `false || echo A && echo B`?

<details>
<summary>Ответ</summary>

`A` и потом `B`. `false` даёт код 1, поэтому `echo A` выполняется (код 0), а затем `&&` запускает `echo B`. Цепочки `&&` и `||` читаются слева направо, поэтому не пиши в них сложную логику, для неё есть `if`.

</details>

### Циклы и арифметика

```bash
for f in *.py; do                         # по списку слов или файлов
  echo "проверяю ${f}"
done

for i in 1 2 3; do echo "попытка ${i}"; done
for i in $(seq 1 5); do echo "${i}"; done # $(...) подставляет вывод команды

n=0
while [ "${n}" -lt 3 ]; do                # пока условие верно
  n=$((n + 1))                            # арифметика в $(( ))
done
```

Ключи `curl -fsS` стоит запомнить: `-f` возвращает ненулевой код на ответах 4xx и 5xx, `-s` убирает индикатор загрузки, `-S` оставляет сообщение об ошибке. Без `-f` `curl` вернёт 0 даже на 500, и скрипт решит, что всё хорошо.

> **Проверь понимание:** зачем в `for f in *.py` нужны кавычки в `"${f}"`, если внутри цикла файлы вроде `my app.py`?

<details>
<summary>Ответ</summary>

Цикл сам разбирает `*.py` правильно и отдаст `my app.py` целиком. Но когда ты потом напишешь `python3 ${f}` без кавычек, оболочка разобьёт значение на `my` и `app.py`. Кавычки нужны при каждом использовании переменной, а не в объявлении цикла.

</details>

### Make: цели, зависимости и TAB

Make (GNU Make) запускает команды по описанию в файле `Makefile`. Это не сборщик для C, а удобная «кнопка» для проектных команд: `make test` одинаково работает у всех.

```text
PORT ?= 8080              # переменная; "?=" берёт значение из окружения, если оно есть

run:                      # цель (target): имя после make
	python3 app.py        # команда (recipe): строка начинается с символа TAB

test: run-check           # зависимость: сначала выполнится run-check
	python3 -m unittest
```

Главная ловушка Make: команда обязана начинаться с символа табуляции (TAB), пробелы дадут ошибку `Makefile:3: *** missing separator.  Stop.`. Каждая строка команды выполняется в отдельной оболочке, а `$` для оболочки удваивается: `$$HOME`. Цель, которая не создаёт файл с таким именем, объявляют так: `.PHONY: run test lint`; иначе, если в каталоге появится файл `test`, `make test` ответит `make: 'test' is up to date.` и ничего не сделает. Значение переменной из командной строки побеждает Makefile: `make run PORT=9000`.

> **Проверь понимание:** зачем `.PHONY` и что случится, если создать файл с именем `test` без него?

<details>
<summary>Ответ</summary>

Make сравнивает цель с файлом на диске. Файл `test` существует, зависимостей нет, значит цель «свежая», и команды не запускаются. `.PHONY` говорит: это имя действия, а не файла, выполняй всегда.

</details>

### Читаем app.py как обычный код

Тебе не нужно быть Python-разработчиком, чтобы прочитать сервис. Схема чтения: конфигурация, маршруты, хранилище. Ищи `os.environ` (какие переменные читает программа), `def do_GET` и `def do_POST` (какие маршруты), `open(` (куда пишет). Так ты за минуту узнаешь, что можно настроить, какие пути проверять `curl`-ом и в какой файл идут данные. Для оператора это главный навык: понять сервис, не спрашивая автора.

2. Создай `Makefile`. Отступ перед командами это символ TAB, а не пробелы:

3. Создай `test_app.py`:

```python
"""Тесты сервиса "Заметки": запускаем настоящий app.py на свободном порту."""
import json
import os
import socket
import subprocess
import sys
import tempfile
import time
import unittest
import urllib.error
import urllib.request
from pathlib import Path

APP = Path(__file__).with_name("app.py")


def free_port():
    # Просим систему выдать любой свободный порт
    with socket.socket() as s:
        s.bind(("127.0.0.1", 0))
        return s.getsockname()[1]


class NotesTest(unittest.TestCase):
    @classmethod
    def setUpClass(cls):
        cls.tmp = tempfile.TemporaryDirectory()
        cls.port = free_port()
        env = dict(os.environ)
        env.update(
            HOST="127.0.0.1",
            PORT=str(cls.port),
            APP_VERSION="test",
            NOTES_DATA=str(Path(cls.tmp.name) / "notes.txt"),
        )
        cls.proc = subprocess.Popen(
            [sys.executable, str(APP)],
            env=env,
            stdout=subprocess.DEVNULL,
            stderr=subprocess.DEVNULL,
        )
        # Ждём до 5 секунд, пока сервер начнёт отвечать
        for _ in range(50):
            try:
                cls.call("GET", "/healthz")
                return
            except OSError:
                time.sleep(0.1)
        cls.tearDownClass()
        raise RuntimeError("сервис не поднялся за 5 секунд")

    @classmethod
    def tearDownClass(cls):
        cls.proc.terminate()
        cls.proc.wait(timeout=15)
        cls.tmp.cleanup()

    @classmethod
    def call(cls, method, path, body=None):
        req = urllib.request.Request(
            f"http://127.0.0.1:{cls.port}{path}", data=body, method=method
        )
        try:
            with urllib.request.urlopen(req, timeout=5) as resp:
                return resp.status, resp.read().decode()
        except urllib.error.HTTPError as err:
            return err.code, err.read().decode()

    def test_root(self):
        status, text = self.call("GET", "/")
        self.assertEqual(status, 200)
        self.assertEqual(text, "Notes service vtest\n")

    def test_healthz(self):
        status, _ = self.call("GET", "/healthz")
        self.assertEqual(status, 200)

    def test_post_and_get_note(self):
        payload = json.dumps({"text": "первая заметка"}).encode()
        status, _ = self.call("POST", "/notes", payload)
        self.assertEqual(status, 201)
        status, text = self.call("GET", "/notes")
        self.assertEqual(status, 200)
        self.assertIn("первая заметка", [n["text"] for n in json.loads(text)])

    def test_not_found(self):
        status, _ = self.call("GET", "/no-such-path")
        self.assertEqual(status, 404)

    def test_empty_body_is_400(self):
        status, _ = self.call("POST", "/notes", b"")
        self.assertEqual(status, 400)

    def test_method_not_allowed(self):
        status, _ = self.call("PUT", "/notes", b"{}")
        self.assertEqual(status, 405)


if __name__ == "__main__":
    unittest.main()
```

## Вопросы с собеседований

### 1. [junior] Скрипт отработал, но «ничего не сделал». В логе пусто, код выхода 0. Что проверишь?

Запущу с трассировкой `bash -x script.sh` и посмотрю, какие команды реально выполнялись. Проверю условия: часто `if [ $VAR = x ]` с пустой переменной или `curl` без `-f`, который вернул 0 на 404. Посмотрю код выхода промежуточных команд и есть ли в скрипте `|| true`, глушащий ошибки.

**Что хотят услышать:** `bash -x`, кавычки вокруг переменных, коды выхода, `curl -f`, подозрение на `|| true` и проглоченный stderr.

**Красный флаг:** «добавлю `sleep`» или «перепишу на Python» без диагностики.

### 2. [junior] Что делает `FILE=$1; rm -rf $FILE/*`, если запустить без аргумента? Как исправить?

`FILE` пустая, оболочка раскроет команду в `rm -rf /*`, то есть попытается удалить всё, до чего дотянутся права. Исправление: кавычки и защита от пустого значения `rm -rf "${FILE:?нужен каталог}"/*`: конструкция `:?` прерывает скрипт с сообщением. Ещё лучше `set -u` (см. [урок 1.7](07-bash-in-ops.md)).

**Что хотят услышать:** подстановка пустой переменной, `${VAR:?}`, `set -u`, проверка `-n`.

**Красный флаг:** «просто не запускай без аргумента».

### 3. [junior] Чем `>`, `>>` и `2>&1` отличаются и что произойдёт при `cmd > out.log 2>&1` и `cmd 2>&1 > out.log`?

`>` перезаписывает файл, `>>` дописывает. В первой форме и stdout, и stderr идут в файл. Во второй stderr сначала привязан к старому stdout (терминалу), потом stdout уходит в файл: ошибки останутся на экране. Порядок редиректов важен.

**Что хотят услышать:** порядок обработки слева направо, дескрипторы 1 и 2, что при `2>&1` в конвейере stderr попадает в pipe.

**Красный флаг:** «это одно и то же».

### 4. [junior] Как узнать, что предыдущая команда завершилась успешно, и как скрипт сообщит об ошибке вызвавшему?

Код выхода лежит в `$?`: 0 успех, иное ошибка. Условия `if` и `&&`/`||` проверяют именно его. Свой скрипт завершаю `exit N`; вызывающий (CI, cron, `make`) остановится или продолжит по этому коду, поэтому по ошибке я выхожу с ненулевым кодом, а не просто печатаю сообщение.

**Что хотят услышать:** `$?`, `exit`, что CI и Make смотрят на код, а не на текст.

**Красный флаг:** «смотрю, есть ли слово error в выводе».

### 5. [junior] `make test` пишет `make: 'test' is up to date.` и ничего не запускает. Почему?

Make считает `test` файлом. Если в каталоге есть файл или каталог `test` и нет зависимостей, цель свежая. Лечится `.PHONY: test`, который помечает цель как действие.

**Что хотят услышать:** `.PHONY`, идея сравнения с файлом на диске.

**Красный флаг:** «удалю Makefile и напишу скрипт» или «`touch` файла».

### 6. [junior] `Makefile:5: *** missing separator.  Stop.` Что это и как найти причину?

В строке команды вместо TAB пробелы (или в строке вообще не команда и не правило). Смотрю `cat -A Makefile`: TAB виден как `^I`. Исправляю отступ на TAB, настраиваю редактор не заменять TAB пробелами для Makefile.

**Что хотят услышать:** TAB, `cat -A`, настройка редактора.

**Красный флаг:** не знает про TAB и переписывает файл целиком.

### 7. [middle] Деплой-скрипт иногда «работает», а иногда после `curl | tar xz` оставляет пустой каталог. Как найти и исправить?

Без `set -o pipefail` код выхода конвейера равен коду последней команды: упавший `curl` теряется, `tar` может завершиться с 0 на пустом вводе. Включаю `set -euo pipefail`, скачиваю в файл, проверяю код и контрольную сумму, потом распаковываю. Подробнее об этом в [уроке 1.7](07-bash-in-ops.md).

**Что хотят услышать:** pipefail, скачивание отдельно от распаковки, проверка SHA256.

**Красный флаг:** «добавлю `sleep` и повторю» или «`|| true`».

### 8. [middle] Скрипт с `for f in $(ls *.log)` ломается на некоторых файлах. Почему и как переписать?

`$(ls ...)` даёт текст, который разбивается по пробелам: файл `my app.log` превращается в два слова. Правильно: `for f in *.log; do ... "${f}" ...; done`, а если файлов может не быть, проверять `[ -e "${f}" ] || continue`. Для рекурсивного обхода `find ... -print0 | xargs -0` или `find -exec`.

**Что хотят услышать:** word splitting, глоббинг оболочкой, `-print0`, кавычки.

**Красный флаг:** «парсить вывод `ls` нормально».

### 9. [middle] В Makefile команда `cd app` на одной строке, а `python3 app.py` на следующей запускается не в том каталоге. Почему?

Каждая строка рецепта выполняется в отдельной оболочке, поэтому `cd` не переносится. Решения: одна строка `cd app && python3 app.py`, обратные слэши для многострочной команды или `.ONESHELL`. Переменные оболочки между строками тоже не сохраняются, а `$` для оболочки пишется как `$$`.

**Что хотят услышать:** отдельный shell на строку, `&&`, `$$`, `.ONESHELL`.

**Красный флаг:** «баг Make».

### 10. [middle] Нужно проверить, что сервис «поднялся» после деплоя, в скрипте выкладки. Как сделаешь и какие ловушки учтёшь?

Цикл с ограничением попыток и таймаутом каждой: `curl -fsS --max-time 2 /readyz`, пауза между попытками, итоговый ненулевой код при неудаче, сообщение в stderr. Проверяю готовность (`/readyz`), а не просто «порт открыт»: процесс может слушать порт, но не уметь писать в хранилище. Пауза без потолка превращается в вечное зависание пайплайна.

**Что хотят услышать:** ограниченный цикл, `--max-time`, `-f`, различие живости и готовности, код выхода.

**Красный флаг:** `sleep 30` и «должно хватить».
